Gates

The exit gate types, what makes each one pass, and why the engine decides rather than you.

Each workflow phase has exit gates. Every one of them is evaluated by the engine against real state rather than self-reported — an AI cannot declare any of them passed. One is human-only by design: manual_confirm passes when you press its button, and no tool exists for an agent to press it.

GatePasses whenExample
min_tasks(n)At least n tasks have been createdThe planning phase needs at least 1 task before work can start
all_tasks_doneThere is at least one task, and every task is done — an empty list does not passFinish the execution phase before moving to review
no_blocked_tasksNo task is blockedYou can’t wrap up while something is stuck
artifact_exists(path)The named output path exists (a file or a directory)artifacts/report.md has to be written for it to count as delivered
min_decisions(n)At least n decisions were recorded after entering this phaseThe review phase needs at least 1 decision on record
manual_confirm(prompt)human onlyYou personally press the confirm button in the app“Output has been inspected by a human” — an AI cannot press this for you
doctor_cleanThe workspace doctor reports no errorsThe handoff layer has to be healthy before the project can close out

human only — only you can satisfy it. The engine evaluates every other gate against real state.

Where gates are written

Section titled “Where gates are written”

Each phase lists its exit gates in .nextup/workflow.json, next to its AI instructions. This is the verify phase of the Software Development template; the files are described in Disk contract.

.nextup/workflow.json (excerpt)
{
  "id": "verify",
  "exitGates": [
    { "kind": "min_decisions", "count": 1 },
    {
      "kind": "manual_confirm",
      "prompt": "All tests pass and the main flows work in a real run"
    }
  ]
}

How a session sees them

Section titled “How a session sees them”

The engine writes the current phase’s gates into the state block of AGENTS.md, the file every session reads first:

AGENTS.md (state block, excerpt)
**Exit gates** (evaluated by the engine against real state):
- [x] min_tasks(1) — 2/1
- [x] min_decisions(1) — 1/1

Note

Ticking a box by hand changes nothing. The block is maintained by the engine, and hand edits are overwritten on the next update.

Forcing a gate

Section titled “Forcing a gate”

If a gate has not passed, advance_phase returns an error. The tool is listed in Hub MCP tools.

Caution

Forcing it through requires a reason, and is written to the ledger and the phase history as an OVERRIDE.

What an AI cannot do

Section titled “What an AI cannot do”

An AI has no permission to force a phase advance, and no permission to satisfy a manual_confirm gate. Both are permanently reserved for humans.
