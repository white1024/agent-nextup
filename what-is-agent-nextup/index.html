What is Agent NextUp?

A desktop app that turns any long-running project into a structure an AI agent can pick up mid-flight.

Agent NextUp is a desktop app that organises any long-running project (writing software, doing research, running a side business, planning your life) into a standard structure that an AI can take over directly:

  • Project (workspace): a folder you choose. All state lives inside it as human-readable files. There is no black-box database: every piece of state you own is a file you can inspect with your file manager or with git, any time. (Two files inside .nextup/ are not text — the search index, which is rebuildable, and the encrypted secret store. Neither holds anything the readable files do not.)
  • Tasks: atomic units of work, each small enough to finish within a single working session, with a status (todo → in progress → done, or blocked; cancelled for work that will not happen).
  • Decisions and memory: each significant choice is recorded with an id in an append-only ledger, approaches you rejected go on a do-not-revisit list, and cross-session memory is kept one fact per file — so the next session inherits the reasoning, not just the result.
  • Handoff snapshot: a summary of “where things stand and what comes next”, maintained automatically by the engine. Switch to a new AI session, a different machine, or a different person: reading this one file is enough to pick up the thread.

In one sentence: you make the decisions, the AI does the work, and Agent NextUp makes sure a handoff is always possible.

The agent doesn’t get to mark its own homework: a task it marks done is only a claim, verifying it is a separate mark that requires evidence, and the tool it would use to mark its own work verified is off by default. On a project that runs in stages, exit gates add a check the engine computes from real state before a phase can close.

How a project runs

Section titled “How a project runs”

A workflow template (software, research, business, life planning, or a generic one) tells the agent how to work. By default a project runs ongoing: work arrives as tasks and gets done one by one, there are no phases to advance, and the template’s working instructions say which skill or check fits which moment — a vague request, breaking work down, finishing a task.

When a project has clear stages and an end point, you can run it staged instead: it moves through the template’s phases (for example plan → execute → review), and each phase has exit gates that the engine evaluates against real state (for example “all tasks are done”) before it lets the project advance. See Gates. You choose when you create the project, and can switch either way later in its settings.

Why this exists

Section titled “Why this exists”

An AI coding session is short and forgetful; a real project is long and full of context. Most of the friction in working with AI agents comes from that mismatch: every new session starts by re-deriving what the last one already knew, and the parts that never got written down get lost.

Agent NextUp puts that context in files the engine keeps fresh, so the next session starts from state rather than from scratch.

What it is not

Section titled “What it is not”
  • Not an AI agent. Agent NextUp doesn’t write your code or your report. It is the management layer; the execution is done by whichever agent you prefer (Claude Code, Codex, Gemini CLI, or you).
  • Not a cloud service. Your project state is local files on your machine, and Agent NextUp itself has no backend to send them to. It does not, however, make any claim about the agent CLIs you run inside it; those talk to their own vendors, with their own credentials, exactly as they would in an external terminal.
  • Not a task tracker you have to feed by hand. The handoff snapshot regenerates on every state change, so it is never staler than your last action.
