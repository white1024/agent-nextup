Building and packaging

Development commands, the test suite, and how installers are produced.

Prerequisites

Section titled “Prerequisites”

Git, rustup (the MSVC toolchain on Windows), and pnpm — the install page’s prerequisites table covers the Windows details. The Rust version is pinned in rust-toolchain.toml; rustup installs it the first time you build, and CI builds with the same one. On Linux and macOS add the standard Tauri v2 system packages for your OS (Tauri’s prerequisites guide lists them; the exact apt set CI uses is in .github/workflows/release.yml). Node is not on the list — the repo pins it and pnpm fetches it, the same way rustup fetches the pinned Rust.

Development

Section titled “Development”
Terminal
pnpm install            # frontend dependencies
pnpm tauri dev          # development mode (hot reload)
pnpm tauri build        # produce an installer

cargo test --workspace  # Rust unit tests (must be fully green before committing)
pnpm build              # strict tsc check + vite bundle
pnpm test               # frontend unit tests (vitest; CI holds a release back if they fail)

You never build the hub server as a routine step — pnpm tauri dev and pnpm tauri build both do it for you (see Packaging below). cargo build --release -p nextup-mcp exists only as the recovery command the app itself prints when the executable has gone missing.

Note

The Node version is pinned by use-node-version in .npmrc; pnpm downloads and uses it automatically, so whatever version is installed on your machine doesn’t matter.

Packaging

Section titled “Packaging”

pnpm tauri build produces the installer (on Windows: MSI and NSIS).

The hub server ships inside the installer. scripts/prepare-sidecar.mjs builds nextup-mcp and stages it; it is wired into both beforeDevCommand and beforeBuildCommand, and Tauri’s externalBin mechanism packages it next to the main executable. After installation the app finds it without any PATH setup.

Windows also gets a portable build — the app and the hub in one zip, no installer. node scripts/make-portable.mjs (after pnpm tauri build) writes target/portable/Agent NextUp_<version>_<arch>_portable.zip; unzip anywhere you can write to and run agent-nextup.exe. It is Windows-only on purpose: Linux’s AppImage is already a no-install format, and an unsigned macOS app served from a zip hits Gatekeeper harder than the dmg does. Two caveats: the portable build cannot fetch the WebView2 runtime for you (the installer can), and AppLocker/WDAC block by execution policy, so they stop a portable exe just the same.

Multi-platform installers are produced by CI (three targets: Windows x64, Linux x64, macOS arm64), and the Windows job builds the portable zip alongside them. Pushing a v* tag runs the frontend and Rust tests on all three platforms, then opens a GitHub release with the installers and the zip attached, together with the signed updater bundles and latest.json that the in-app updater reads (releases up to 0.1.3 were marked pre-release, which hides them from GitHub’s “latest” and so from the updater); workflow_dispatch uploads the installers as workflow artifacts instead, without updater bundles. The release starts as a draft and is published only once every platform has passed its tests and built — a red test anywhere means no release, rather than one missing a platform. Tagged builds go to the releases page; take the newest. Building an early tag from source has one trap worth naming: the ad-hoc signature described below arrived partway through, and a macOS bundle built before it does not open at all.

Unsigned builds

Section titled “Unsigned builds”

Nothing here is signed with a publisher certificate and nothing is notarized, so every OS stops the first launch. macOS bundles do carry an ad-hoc signature (bundle.macOS.signingIdentity: "-"), which identifies no publisher — it only makes the bundle structurally valid, so that Gatekeeper’s refusal is the recoverable kind rather than “the application is damaged”.

  • Windows — SmartScreen blue box → “More info” → “Run anyway” (the installer and the portable exe alike).
  • macOS — Gatekeeper refuses the first launch because the build is not notarized. Open System Settings → Privacy & Security, find the blocked app near the bottom of the pane, and click Open Anyway. Control-clicking the app and choosing “Open” is no longer a reliable bypass on current macOS. The command-line equivalent strips the quarantine flag instead — quote the path, it contains a space: xattr -dr com.apple.quarantine "/Applications/Agent NextUp.app".
  • Linux — chmod +x the AppImage before running it; for the deb, sudo apt install ./Agent*.deb. The filename contains a space, so keep it out of the pattern — a literal space would split the argument before the glob ever runs, while the glob’s own result is a single word.

Updater signing

Section titled “Updater signing”

The in-app updater (from 0.2.0) only installs a bundle whose signature matches the public key in tauri.conf.json (plugins.updater.pubkey). The private key never enters the repository: CI reads it from the TAURI_SIGNING_PRIVATE_KEY secret of the public repository, and the release workflow turns on bundle.createUpdaterArtifacts for tag builds only. That is why a local pnpm tauri build and a manual workflow run still work without the key — they simply produce no updater bundles.

To produce signed bundles locally, point the build at a key and enable the artifacts for that one run:

Terminal
TAURI_SIGNING_PRIVATE_KEY="$(cat <path to the private key>)" TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""   pnpm tauri build --config '{"bundle":{"createUpdaterArtifacts":true}}'

The key goes in by content. tauri signer generate also lists a TAURI_SIGNING_PRIVATE_KEY_PATH variable, but the CLI this project pins does not read it — with only that set, the bundles build and the signing step fails with “a public key has been found, but no private key”.

A fork that wants its own updates needs its own key pair (pnpm tauri signer generate), its public key in tauri.conf.json, and its own endpoint — an installed copy only trusts bundles signed by the key it was built with.
