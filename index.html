Every new session starts by re-deriving what the last one already knew. Agent NextUp keeps the project's state in human-readable files an agent can take over from — and what an agent calls done stays a claim until it is verified with evidence.

Open it

There is no database. This is the whole product.

A workspace is a folder you chose. Every piece of state is a file you can open, diff, and commit. Snapshots and indexes are rebuildable derivatives; the ledger is append-only and is the audit record.

The lid

The block your agent reads first

AGENTS.md is the file any agent host reads first. The engine rewrites its fenced block on every state change — task, decision, milestone, phase advance. Anything you write outside the fence is never touched.

The hub

What the hub exposes

The hub is a local MCP server bundled with the app. It can expose 49 tools to an agent; 14 of 18 write tools are granted on day one, and the other 4 wait until you allow them.

  • One master switch decides whether agents reach the hub at all.
  • You tick a capability group, not one box per tool.
  • Every call, including denied ones, lands in the ledger.

One agent call

How those files got there

The folder and the AGENTS.md block above are what one agent call leaves behind. The agent asks; one gate decides what it may change; whatever it does change lands as a file you can open.

Gates

The engine marks the sheet

A project run in stages closes each phase on exit gates, evaluated against real state. Nothing here is self-reported. manual_confirm is the inverse: only a person can satisfy it, and no tool exists for an agent to do so.

  • Forcing any gate demands a reason.
  • Every override is written to an append-only ledger.
  • Each phase keeps its exit gates in workflow.json.

Five guarantees

What the structure buys you

None of this depends on your agent remembering to behave. The files and the engine hold five guarantees, whichever agent you run.

  • The snapshot regenerates on every state change.
  • Verification is a separate mark that wants evidence.
  • The engine blocks work whose prerequisites are not done.
  • Deliveries move when you press send or turn on auto-send.

Every day

The loop

Break down, do the work, record decisions, pass the gate if the project runs in stages, hand off. The next session reads the regenerated snapshot and picks up the thread.

  • Each task is small enough to finish in one session.
  • Blocked needs a reason.
  • Forcing a gate is recorded as an override.

Templates and CLIs

Runs the agent CLIs you already use

The built-in terminal runs Claude Code, Codex CLI, Gemini CLI, or a plain shell. The Claude CLI picks up .mcp.json and connects to the hub automatically; other vendors' CLIs do not.

  • Sessions belong to the app; switching projects doesn't interrupt them.
  • A running terminal can pop out into its own window.
  • Five built-in workflows; add your own as a JSON file.
